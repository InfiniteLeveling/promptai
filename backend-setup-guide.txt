1. ARCHITECTURE & REPOSITORY OVERVIEW
===============================================================================
The PromptArchitect AI backend has been rebuilt from a legacy single-file Express
JSON backend into a production-grade, multi-tenant cloud architecture:

* Fastify 5.x Server: High-throughput API gateway with Zod schema validation,
  Helmet security headers, strict CORS, and structured Pino logging.
* Pure Compiler Pipeline (@promptarchitect/compiler): Deterministic 7-stage AST
  orchestration engine without database or HTTP side-effects.
* Canonical Type Contracts (@promptarchitect/contracts): Shared TypeScript types,
  Draft-07 JSON schemas, and Ajv runtime validation.
* Supabase PostgreSQL: 18 relational tables with Row Level Security (RLS),
  deterministic UUID keys, immutable audit ledgers, and atomic stored procedures.
* Double-Entry Quota Ledger: Prevents concurrency race conditions, credit theft,
  and cross-UTC quota leaks using reservation and commit transactions.
* Background Compilation Worker: Polling daemon using Postgres row-level locks
  (FOR UPDATE SKIP LOCKED) with lease heartbeats and retry backoff.
* 100% Legacy Parity: Full backward compatibility with the React frontend for all
  15 legacy endpoints (/api/prompts, /api/templates, /api/usage, /api/ingest/*).

Folder Structure:
  prompt-maker/
  ├── packages/
  │   ├── contracts/            <- Shared TypeScript interfaces & JSON schemas
  │   └── compiler/             <- 7-stage pure compiler AST pipeline
  ├── src/
  │   ├── app.ts                <- Fastify application builder & middleware
  │   ├── server.ts             <- Fastify HTTP server entrypoint (Port 3000)
  │   ├── modules/
  │   │   ├── auth/             <- Supabase JWT verification & guest handling
  │   │   ├── billing/          <- Stripe subscriptions & webhook handler
  │   │   ├── blueprints/       <- Enterprise template blueprints repository
  │   │   ├── compilation/      <- Sync & async compilation runs
  │   │   ├── jobs/             <- Background worker daemon (workerRunner.ts)
  │   │   └── storage/          <- Supabase Storage signed URLs & MIME guard
  │   ├── compatibility/        <- Legacy Express /api route compatibility layer
  │   └── infrastructure/       <- Supabase client, Pino logger, SSRF filter
  ├── supabase/
  │   ├── migrations/           <- 4 production SQL migration scripts
  │   └── seed.sql              <- Plans, entitlements & enterprise blueprints
  ├── scripts/
  │   ├── migrate-legacy.ts     <- Legacy db.json to Supabase migration runner
  │   ├── verify-migration.ts   <- SHA-256 data integrity verification runner
  │   └── verify-production-gates.ts <- 6-gate enterprise configuration validator
  └── tests/                    <- 19 Vitest test suites (120 tests)

2. PREREQUISITES
===============================================================================
Before setting up the backend, ensure you have the following installed/ready:

1. Node.js:
   - Version: Node.js 20.x or 24.x LTS (Recommended: v24.20.0 or v20.x)
   - Verify in terminal:
       node -v
       npm -v

2. Supabase Account:
   - Create a free account at: https://supabase.com
   - Create a new project (e.g., "promptarchitect-ai")
   - Note your Project URL and API Keys (Anon Publishable & Service Role Secret)
   - Alternatively, you can use local Supabase via Docker CLI:
       npx supabase init
       npx supabase start

3. Google Gemini AI API Key (Optional but recommended for live LLM runs):
   - Obtain a key from Google AI Studio: https://aistudio.google.com/
   - Key format: AQ.Ab8RN... or AIzaSy...

4. Git:
   - To track codebase versions and synchronize branches.

5. STEP 3: EXECUTE SUPABASE DATABASE MIGRATIONS
===============================================================================
You must execute the 4 migration scripts and the seed script in order.

METHOD A: Via Supabase Web Dashboard (Recommended for hosted Supabase)
1. Go to your Supabase Project Dashboard: https://supabase.com/dashboard
2. In the left navigation menu, click "SQL Editor".
3. Click "New query".
4. Copy, paste, and run each of the following files IN NUMERICAL ORDER:

   Query 1: supabase/migrations/20260906000001_initial_schema.sql
     -> Creates all 18 tables: users, plans, subscriptions, prompts,
        blueprints, compilation runs/jobs/attempts, quota ledgers, etc.
     -> Sets up immutability triggers and automatic auth.users user profile sync.
     -> Click "Run" (ensure "Success. No rows returned" is shown).

   Query 2: supabase/migrations/20260906000002_rls_and_security.sql
     -> Enables Row Level Security (RLS) on all 18 tables.
     -> Applies strict tenant isolation policies so users only access their data.
     -> Sets up column-level security and admin authorization helper.
     -> Click "Run".

   Query 3: supabase/migrations/20260906000003_quota_functions.sql
     -> Creates stored procedures:
          * reserve_compilation_quota()
          * commit_compilation_quota()
          * refund_compilation_quota()
          * recover_stale_quota_reservations()
     -> Enforces concurrency safety and credit guarantees.
     -> Click "Run".

   Query 4: supabase/migrations/20260906000004_job_and_worker_functions.sql
     -> Creates stored procedures:
          * claim_next_compilation_job() (Uses FOR UPDATE SKIP LOCKED)
          * worker_heartbeat() (Extends job lease)
          * finalize_compilation_job() (Records tokens, cost, completion)
     -> Click "Run".

   Query 5: supabase/seed.sql
     -> Seeds subscription tiers: 'free' (100 req/mo), 'pro' (2,000 req/mo),
        and 'developer' (10,000 req/mo).
     -> Seeds 5 production blueprints (Enterprise Payment Reconciler, Multi-Agent
        Orchestration, E-Commerce Platform, Microservices Mesh, RAG Pipeline).
     -> Click "Run".

METHOD B: Via Supabase CLI (If using Supabase CLI locally)
1. Link to your project:
   npx supabase link --project-ref your-project-ref
2. Push all migrations:
   npx supabase db push

6. STEP 4: CONFIGURE SUPABASE AUTHENTICATION
===============================================================================
PromptArchitect AI supports both registered users (Email/Password) and anonymous
guest users.

1. Open your Supabase Dashboard -> "Authentication" -> "Providers".
2. Under "Email":
   - Ensure "Enable Email provider" is turned ON.
   - For local development, you may uncheck "Confirm email" to log in instantly.
3. Under "Anonymous Sign-Ins":
   - Turn ON "Allow anonymous sign-ins".
   - This allows users to test prompts and generate specs immediately without
     having to sign up first.
4. (Optional) URL Configuration:
   - In "Authentication" -> "URL Configuration", set "Site URL" to:
     http://localhost:5173 (or your deployed frontend domain).

7. STEP 5: CREATE SUPABASE STORAGE BUCKETS
===============================================================================
PromptArchitect AI uses Supabase Storage for user attachments and avatars.

1. Open your Supabase Dashboard -> "Storage".
2. Create Bucket 1:
   - Name: prompt-attachments
   - Public bucket: Disabled (Keep PRIVATE for security)
   - Allowed MIME types: image/png, image/jpeg, image/webp, application/pdf, text/plain
   - File size limit: 10 MB
3. Create Bucket 2:
   - Name: user-avatars
   - Public bucket: Enabled (or Private with signed URLs)
   - Allowed MIME types: image/png, image/jpeg, image/webp
   - File size limit: 5 MB

11. STEP 9: MIGRATE LEGACY DATA (IF UPGRADING FROM DB.JSON)
===============================================================================
If you have legacy prompts, templates, or usage counters in "server/data/db.json":

1. Run the legacy migration script:
   npm run migrate:legacy
   (or: npx tsx scripts/migrate-legacy.ts)

   This script:
   - Acquires an atomic migration lock in Supabase to prevent concurrent runs.
   - Computes a SHA-256 checksum of server/data/db.json.
   - Generates deterministic UUIDs from legacy string IDs (e.g., prompt_123).
   - Migrates legacy users, prompts, blueprints, and quota ledgers.
   - Generates "scripts/migration-report.json".

2. Run the migration verification script:
   npm run verify:legacy
   (or: npx tsx scripts/verify-migration.ts)

   This verifies:
   - Every legacy prompt and blueprint exists in the database.
   - SHA-256 source hash matches.
   - Output shows: "Migration verified 100% valid!"

13. STEP 11: START THE ASYNCHRONOUS COMPILATION WORKER
===============================================================================
In a separate terminal window, start the background compilation worker daemon.
This process continuously monitors the queue and executes async compilation jobs:

   npm run worker
   (or: npx tsx src/modules/jobs/workerRunner.ts)

Terminal output:
   {"level":30,"workerId":"worker-01","pollIntervalMs":2000,"msg":"PromptArchitect Compilation Worker started"}

Worker Capabilities:
- Polls Supabase for queued compilation jobs using RPC claim_next_compilation_job().
- Uses FOR UPDATE SKIP LOCKED to guarantee no two workers process the same job.
- Sends heartbeat pings every 15 seconds to maintain job lease.
- Automatically executes the 7-stage compiler pipeline on the job payload.
- Periodically triggers recover_stale_quota_reservations() to refund unused
  reservations from crashed processes.

15. STEP 13: VERIFY API ENDPOINTS (CURL CHEAT SHEET)
===============================================================================
Run these curl commands from any terminal to verify server endpoints:

1. Health Check:
   curl -i http://localhost:3000/health
   Response: 200 OK
   {"status":"ok","timestamp":"...","uptime":...,"version":"3.0.0"}

2. Get Templates / Blueprints:
   curl -i http://localhost:3000/api/templates
   Response: 200 OK (Returns array of blueprints)

3. Get User Usage & Quota:
   curl -i http://localhost:3000/api/usage
   Response: 200 OK
   {"success":true,"data":{"used":...,"limit":100,"remaining":...}}

4. Fetch All Prompts:
   curl -i http://localhost:3000/api/prompts
   Response: 200 OK (Returns array of prompts)

5. Synchronous Compilation Pipeline:
   curl -i -X POST http://localhost:3000/api/v1/compilation/sync \
     -H "Content-Type: application/json" \
     -d "{\"prompt\":\"Build a SaaS billing dashboard with Stripe and React\",\"selectedChips\":[\"react\",\"typescript\"],\"targetAgent\":\"antigravity\"}"
   Response: 200 OK (Returns canonical compiled spec and diagnostic score)

6. Submit Asynchronous Compilation Job:
   curl -i -X POST http://localhost:3000/api/v1/compilation/async \
     -H "Content-Type: application/json" \
     -d "{\"prompt\":\"Synthesize microservices architecture\",\"targetAgent\":\"cursor\"}"
   Response: 202 Accepted (Returns { "jobId": "...", "status": "queued" })

17. TROUBLESHOOTING & FAQ
===============================================================================

Q1: Fastify fails to start with "listen EADDRINUSE: address already in use :::3000"?
A1: Another process is using port 3000 (such as the legacy server or another app).
    To resolve:
    - On Windows (PowerShell):
        Get-Process -Id (Get-NetTCPConnection -LocalPort 3000).OwningProcess | Stop-Process -Force
    - Or change PORT in ".env" to 3001:
        PORT=3001
        (Update VITE_API_URL in frontend/.env accordingly).

Q2: Supabase returns "JWT expired" or "401 Unauthorized"?
A2: Ensure your SUPABASE_ANON_KEY and SUPABASE_SERVICE_ROLE_KEY are copied
    accurately without trailing spaces or newline characters from the Supabase
    dashboard.

Q3: Migrations fail with "relation already exists"?
A3: If tables were already partially created, run:
    DROP SCHEMA public CASCADE;
    CREATE SCHEMA public;
    GRANT ALL ON SCHEMA public TO postgres;
    GRANT ALL ON SCHEMA public TO public;
    Then re-run the 4 migration scripts and seed.sql.

Q4: Gemini AI fails with "API key not valid"?
A4: Check that AI_API_KEY is set in ".env". If empty, the backend automatically
    falls back to mock AI generation in development/test mode so your workflow
    is never blocked.

Q5: CORS error in browser console when calling backend?
A5: Ensure ALLOWED_ORIGINS in ".env" includes your frontend URL:
    ALLOWED_ORIGINS=http://localhost:5173,http://localhost:3000
